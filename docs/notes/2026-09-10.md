# Working Notes: 2026-09-10

## Audit baseline

- Backend tests passed 3/3 only when invoked from `backend`, but their fixture dropped the active database and recursively deleted the shared artifact directory.
- Frontend tests passed 1/1 and the production build passed.
- Frontend lint failed with three errors and three warnings related to state-setting effects and missing dependencies.
- The production JavaScript bundle was 547.56 kB before gzip and triggered the build warning.
- The public repository had no GitHub Actions workflow and no detected license.
- The demand workload used `train_test_split`, so its forecasting label overstated the evaluation protocol.
- The README included three generated images, but the primary comparison plotted classification F1 beside inverse regression RMSE on one axis.

## Implementation direction

Prioritize evidence over feature count. The 1.1 release will make tests non-destructive, make the forecasting protocol chronological, add baseline comparisons and richer artifacts, and show the actual product interface in the README.

## Completed observations

- Backend tests now use a fresh temporary database and artifact directory for every test.
- Demo generation resets only the ignored `.demo-runtime/` sandbox.
- Demand evaluation now uses an ordered holdout and beats lag-7 seasonal naive RMSE by 3.89 percent on the fixed demo seed.
- Classification scorecards expose precision, recall, threshold, and confusion counts.
- Frontend charts are lazy-loaded, reducing the main production bundle from 547.56 kB to 195.03 kB.
- The README now leads with a real dashboard screenshot and separates classification metrics from forecast-error comparisons.
